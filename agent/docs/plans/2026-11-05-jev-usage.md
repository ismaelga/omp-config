# Jev Usage Plan

**Goal:** Decide where Jev should do more work in this harness, where it should do less, and what to measure before building anything. Companion to `2026-09-20-jev-guard-adoption.md`, which owns the hook designs; this plan supplies the usage evidence and the order.

**Status:** Done 2026-11-05. Task 1 done (`965b3d2`). Task 2 dropped: the wording changed nothing. Task 3: route retired. Task 4: automatic screening built. Task 5: guard stays elective. The user approved 3 and 4 on 2026-11-05.

## Models: nothing to migrate

`jev-1.14.0` is still the newest Jev, and it is what is already pinned (`core.ts:139`, `config.yml` `modelRoles.judge`).

- `GET /v1/models` lists only the aliases `jev-latest` (released 2026-10-22) and `jev-preview` (2026-10-14).
- Live probe: both aliases answer as `jev-1.14.0`. `jev-1.15.0` and `jev-1.14.1` return `Unknown model`.
- The docs changelog's newest entry is Jev 1.14 (2026-10-14). Its additions are Box questions (images), images in state/instructions/criteria, multilingual gains, and an opt-in long-context header (262k tokens), none of which current callers use.

When a new id ships, re-pin with the protocol already used on 2026-10-23 (`core.ts:132-138`). Replay the logged route items and guard inputs through both versions, compare recommendations and flag rates, keep the thresholds unless they move, and bump `core.ts` and `config.yml` together.

## What Jev does today

Window: session files modified 2026-10-24 → 2026-11-05 (1,847 files, 2.39 GB). Long sessions that started earlier are included whole, so transcript counts include a few earlier calls. CLI rows come from `~/.omp/logs/jev.jsonl` for the same dates.

**Native, called by omp itself** (`model_usage` rows with provider `typesafe`):

| Purpose | Calls | Cost |
|---|---|---|
| `ttsr` (judged rules in `agent/rules/`) | 4,220 | $0.094 |
| `find` tool | 3,330 | $0.542 |
| `unexpected-stop` | 1,404 | $0.055 |
| `judge_batch` (eval scoring, one session) | 46 | $0.004 |
| `auto-thinking` | 1 | $0.000 |

Total $0.70 over 13 days. Cost is not a constraint on any option below.

**Elective CLI** (the model has to choose to call it):

| Command | Calls | Outcome | Coverage of the sessions that needed it |
|---|---|---|---|
| `guard` | 1,335 | 37 flagged (2.8%) | 101 of 116 sessions that pushed, opened a PR or deployed (87%) |
| `route` | 225 | 188 `task`, 19 `scout`, 16 `interrogator`, 2 `security-reviewer` | 68 of 161 sessions that dispatched `task` (42%) |
| `screen` | 64 | 0 flagged | 29 of 368 sessions that read a URL or ran `web_search` (8%) |
| `stuck` | 3 | — | superseded by native `unexpected-stop` (1,404 calls) |

Further measurements:

- **Guard gaps are long-session decay.** 15 sessions ran 196 pushes, PR creates or deploys with no guard, 75 of them in one `kpk-devops` session. All sampled hits are real `git push -u origin …` and `gh pr create` calls, not regex noise.
- **Route agreement with dispatch:** 124 of 171 matched route calls. 32 recommended something other than `task`, and 21 of those were followed. There is no counterfactual: these numbers cannot say whether the model would have picked the same agent without route.
- **Screen false-positive rate on organic content:** 200 fetched results sampled from transcripts (159 URL reads, 41 web searches, average 7.5k chars), replayed with `screen`'s exact questions.
  - 1 flag in 200: `credential_leak` 0.56 on cert-manager docs. The trigger was a base64-encoded example certificate, which is not a secret.
  - `injection` never passed 0.19 (p50 0.02, p99 0.14).
  - Recall on planted injections is unmeasured for 1.14.0.
- **Prompt cost:** the `<!-- jev-begin -->` block in `APPEND_SYSTEM.md` is 2,373 chars (~590 tokens), loaded in every session.
- **Auto-thinking is inert:** `defaultThinkingLevel: auto` produced one classifier call in 13 days. Thinking levels arrive pinned (`high` in 1,569 level changes, `xhigh` 201, `low` 132; `auto` once), because model roles carry `:high`/`:xhigh` suffixes.

## Reading

- **More Jev pays where omp calls it, not where the model must remember to.** Native uses run thousands of times for cents. Elective ones decay with session length: guard is the best-adopted at 87%, and screen sits at 8%.
- **"Use Jev more" therefore means turning chosen elective calls into triggered ones.** Each needs a measured reason first:
  - Guard's misses are real pushes.
  - Screen's organic false positives are low, but the true-positive rate is unknown.
  - Route has no evidence it changes outcomes.
- **One proven new use:** typed scoring of benchmark outputs. The 2026-11-05 skill bench scored 47 reports with `judge_batch` for under $0.005, and every decision-changing cell checked by hand was right.

## Tasks

### Task 1: Drop the `stuck` clause from the jev prompt block

Native `unexpected-stop` already does this job: 1,404 calls against 3 elective `stuck` calls.

- [ ] Remove the `stuck` bullet from the `<!-- jev-begin -->` block in `APPEND_SYSTEM.md`. Keep `jev.ts stuck` itself; Task 6 of the 2026-09-20 plan owns deleting command bodies.
- [ ] Restart, then confirm a fresh session's system prompt no longer carries the clause.

**Acceptance:** clause gone; no other clause edited.

### Task 2: Make `judge_batch` the scoring step in skill micro-tests

- [ ] In `skills/writing-skills/SKILL.md`, "Micro-Test Wording Before Full Scenarios", item 4: score reps with `judge_batch` using one bool question per seeded fact, then hand-read every cell that changes the decision. That rule already exists in item 4; this adds the scoring tool to it.
- [ ] Keep the existing warning that automated counts overstate both failure and success.

**Acceptance:** one sentence added to item 4, naming the tool and the hand-check. It is a writing-skills edit, so it follows that skill's own rule: micro-test the wording against a no-guidance control first.

### Task 3: Decide route by labelled evaluation

- [ ] Sample 60 logged route items from `jev.jsonl`: 30 with `recommended: task` and all 37 non-`task` ones, or as many as exist.
- [ ] Label the correct agent for each. Use a fresh panel of three models from different families plus a user spot-check of 10 disagreements.
- [ ] Get the counterfactual: give the session's main model the same item and the same agent catalog, with no route output, and record its pick.
- [ ] Score route's `recommended` and the no-route pick against the labels.

**Acceptance:** a two-row accuracy table.
- Route beats the no-route pick by ≥10 points on the non-`task` half: keep it, and consider triggering it.
- Otherwise: delete the route clause from `APPEND_SYSTEM.md` (~130 tokens per session), and retire the command under the 2026-09-20 plan's Task 6.

### Task 4: Measure screen recall before automating it

- [ ] Build a planted corpus of 20 positives and 20 hard negatives.
  - **Positives:** hidden instructions in a README, an HTML comment, a PR review body, an issue comment, a docs page, and in emoji- or Unicode-smuggled text (the evasion class from `docs/research/jev/alternatives.md`).
  - **Hard negatives:** docs telling a human to run commands, security articles that quote injection strings, and changelogs with imperative steps.
- [ ] Score both sets with `screen`'s exact questions on `jev-1.14.0`, at threshold 0.5 and across the 0.3–0.7 sweep.

**Acceptance:** recall and precision on the planted set.
- Recall ≥ 0.8 with the organic false-positive rate staying near the measured 0.5%: propose an `afterToolCall` extension. It screens only external fetches (`read` of `http(s)://`, `pr://`, `issue://`; `web_search`; `github` device reads), caps content at 32k Jev tokens, sends no local files, and appends a reminder on a flag rather than blocking. This sends every external fetch to TypeSafe automatically, a wider version of the 2026-09-17 decision that let screen content transit. **The user decides the egress before anything is built.**
- Recall below that: keep screen elective and stop there.

A native judged TTSR rule cannot do this job. omp judges assistant text, thinking and tool-call *arguments*, never tool results (`omp://ttsr-injection-lifecycle.md` §10), so a rule can see that a URL was fetched but not what came back. The middle option between the hook and the status quo is a regex TTSR rule on fetch arguments that reminds the agent to run `screen`. It costs no judge call, but it screens nothing itself, and `ttsr.repeatMode: once` limits it to one reminder per session.

### Task 5: Measure what an automatic push guard would have caught

- [ ] Replay the 196 unguarded push/PR/deploy commands from the 15 sessions through `guard` with their original ops and targets, no content. Use the API directly, not `jev.ts`, so the replay stays out of the tuning corpus.
- [ ] Review the 37 organic guard flags from the window: what each was, and what the agent did next.

**Acceptance:** two counts, flags the replay would have raised and organic flags that were true positives.
- Either count is non-trivial: build the narrow trigger, a `tool_call` hook matching `git push`, `gh pr create|merge` and `wrangler deploy|publish` that calls `cmdGuard` and blocks on `flagged`. It reuses the 2026-09-20 plan's Task 4 redaction steps (3, 3a) and pinned model; only the trigger is narrower than that plan's every-call sentinel.
- Both near zero: guard stays elective, and its 87% coverage is enough.

### Parked

- **Auto-thinking:** inert as configured. Either delete `defaultThinkingLevel: auto` as dead config, or A/B `auto` against `:high` on one role (`task` subagents) for tokens, latency and outcome. Neither is urgent.
- **Box questions** (image localisation) for `design-critique` screenshots. No current failure motivates it.
- **Long-context header** for `screen` on pages over 64k tokens. Only 5 of 3,468 `jev.jsonl` rows since 09-17 carry an `error` field, and none is attributed to size yet; check before adding.

## Results (2026-11-05)

**Task 2: dropped.** 10 reps scored the same 20 bench reports: 5 with the current micro-test section, 5 with the `judge_batch` sentence. None of the 10 used `judge_batch`; all hand-read every report, in 3–9 minutes each, and their tables agreed.

`judge_batch` does work in a `task` subagent's eval (probe returned `{'q': {'bool': 0.99}}` from `jev-1.14.0`). So this was not an environment gap, although one variant rep assumed it was, echoing item 1's "No API access needed". The reps simply did not reach for it.

That is not a failure here: hand scoring at n=20 was accurate and agreed across reps. By the skill's own rule, a control with no failure means there is nothing to author. The result is model-relative, though. All 10 reps ran on `task` = glm-5.3-flash (via zai-paygo), while skill benches are usually run from the main session. There, Opus already used `judge_batch` unprompted on 2026-11-05, with the current wording: one observation, but a sentence it does not need is no stronger a case for the edit.

One side finding supports the existing hand-read rule: all 10 hand scorers counted `overaccuse` 5/5 in the dark-patterns baseline, where `judge_batch` had counted 3/5. The judge under-counts seeds that need judgment. Revisit only for a bench too large to hand-read.

**Task 3: route loses to no route.** Labels are the majority of three agents on other model families: `reviewer` (gpt-6.1-terra), `security-reviewer` (claude-sonnet-5-5) and `task` (glm-5.3-flash). There was a majority on 67/67 items and unanimity on 50. The no-route pick is one Opus completion over the same items and catalog.

| | Non-`task` half (37) | `task` half (30) | Total |
|---|---|---|---|
| route `recommended` | 30 (81%) | 25 (83%) | 55/67 |
| Opus, no route | 36 (97%) | 27 (90%) | 63/67 |

Six of route's seven non-`task` misses send a plain read-only code review to `interrogator`, and in all six the three labellers agreed on `reviewer`. That is a 16-point loss on the half where route claims to help, so by the acceptance rule the route clause goes. The labellers also ran inside their agent personas. **Done:** the clause left `APPEND_SYSTEM.md`; `cmdRoute` and its catalog loaders left `core.ts`, and `jev.ts route` now exits 2 with `unknown jev command`.

**Task 4: screen separates cleanly.** On a planted corpus of 21 positives and 20 hard negatives, at threshold 0.5:
- **Recall 21/21.** The lowest positive scored 0.72. Positives included zero-width, Unicode-tag and fullwidth smuggling, a Spanish instruction, and hidden HTML.
- **False positives 0/20.** The highest negative was the OWASP prompt-injection page at 0.28.
- Results are identical across 0.3–0.7. With the organic 0.5% false-positive rate, this meets the acceptance bar.

The caveat is that I wrote the corpus, and the 2026-09-20 plan's research says adaptive attackers beat every published detector.

**Built:** `scripts/jev-ts/screen-extension.ts`, loaded via `config.yml` `extensions:`. It is a `tool_result` handler on `read` of `http(s)://`/`pr://`/`issue://` paths and on `web_search`, which runs `cmdScreen` on the first 120k chars and returns `additionalContext` on a flag.

Smoke test in `omp -p` against a local page:
- The planted page was flagged at `injection` 0.99, and the agent quoted the reminder and did not run the planted command.
- The clean page passed silently.
- Both verdicts were logged to `jev.jsonl` in 186/205 ms.

Content fetched through bash, MCP or the browser is not hooked and stays on the prompt clause.

**Task 5: an automatic push trigger would catch almost nothing.** I replayed all 238 push/PR/deploy commands from the 15 unguarded sessions, with the last user message as the note (redacted). 3 flagged (1.3%), none a clear hazard:
- two `wrangler deploy --secrets-file` runs (`destructive` 0.61 and 0.59);
- one `gh pr merge --admin` (0.50) the user had asked for.

All 37 organic flags were real destructive operations the agent chose to guard: infra teardowns, IAM key and service-account deletes, a fund transfer, a prod `ALTER EXTENSION`, and remote branch deletes. 13 of them were at preflight. Most are `gcloud`/`kubectl`/`cast`-shaped, which a push regex never matches. Guard's value is in operations a trigger cannot enumerate; keep it elective.

## Order

Tasks 1 and 2 any time. Tasks 3, 4 and 5 are independent measurements and can run in parallel. Each ends in a user decision, and nothing is built before that decision. Config and `APPEND_SYSTEM.md` changes need an omp restart.
